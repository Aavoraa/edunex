EDUNEX SMART SCHOOL 360 - HOW TO RUN
======================================

Project folder:  C:\Users\USER\ui ux\edunex\Application
Needs:           Node.js 20 or newer, PostgreSQL (already installed on this PC)

All commands below are run from the project folder, in PowerShell or Git Bash.

What you get:
  - Website (React)            http://localhost:5173
  - Common REST API            http://localhost:4000/api
  - API documentation          http://localhost:4000/api/docs
  - PostgreSQL database        localhost:5544, database "edunex"
  - Paper Correction service   http://127.0.0.1:8006 (internal; see section F)


----------------------------------------------------------------------
QUICK START (this PC, everything already set up)
----------------------------------------------------------------------

  1. Start the database (PowerShell):
       & "C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe" -D .\.pgdata -o "-p 5544" -l .\.pgdata\server.log start

  2. Start the API and the website:
       npm run dev

  3. Open http://localhost:5173 and sign in (see section C).

  To stop: Ctrl+C in the terminal, then optionally
       & "C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe" -D .\.pgdata stop


----------------------------------------------------------------------
A. FIRST TIME ONLY (or on a new machine)
----------------------------------------------------------------------

1) Install packages

   npm install

2) Settings file (.env)

   The file ".env" in the project folder holds the settings. On this PC it
   already exists. On a NEW machine copy .env.example to .env and fill in:

     DATABASE_URL        database connection
                         (this PC: postgres://postgres:...@localhost:5544/edunex)
     JWT_SECRET          long random value
     JWT_REFRESH_SECRET  a different long random value
     SEED_DEMO_PASSWORD  the password given to every demo account

   Generate a random secret with:
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

   Request limits (per 15 minutes, per computer address):
     RATE_LIMIT_MAX        all API requests  (this PC: 50000 for testing)
     AUTH_RATE_LIMIT_MAX   sign-in attempts  (this PC: 200)

3) Database

   This PC uses a private PostgreSQL cluster in the ".pgdata" folder on
   port 5544. Your installed PostgreSQL 17/18 services are not touched.

   Start it (PowerShell):
     & "C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe" -D .\.pgdata -o "-p 5544" -l .\.pgdata\server.log start

   On a NEW machine, either:
     - create a private cluster (PostgreSQL binaries on PATH, or set PG_BIN):
         set LOCAL_PG_PASSWORD=choose-a-password   (PowerShell: $env:LOCAL_PG_PASSWORD="...")
         npm run db:local:init
       then later: npm run db:local:start / npm run db:local:stop
     - or point DATABASE_URL at any PostgreSQL 15+ database you already have.

4) Create the tables and load the sample data

   npm run db:reset

   This DROPS and recreates everything in the database named in
   DATABASE_URL, runs all migrations, then loads fictional sample data:
   about 300 students (at least 5 in every class section), staff,
   parents, fees, payroll, admissions, academics,
   transport and sample GPS coordinates. Dates are generated relative to
   today, so the dashboards always look current. Re-run it any time you
   want a fresh demo (for example the next day).


----------------------------------------------------------------------
B. EVERY TIME
----------------------------------------------------------------------

1) Make sure the database is running.
   Check (PowerShell):
     & "C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe" -D .\.pgdata status

2) Start the API and the website together:

     npm run dev

   Or in two separate terminals:
     npm run dev:api        (API on port 4000, restarts when code changes)
     npm run dev:web        (website on port 5173)

3) Open http://localhost:5173 in the browser.

4) Stop: press Ctrl+C in the terminal(s).

----------------------------------------------------------------------
E. PROBLEMS
----------------------------------------------------------------------

  "Invalid environment configuration"
      -> .env is missing or a value is wrong. Compare with .env.example.

  "ECONNREFUSED ... 5544" / database errors
      -> the database is not running. Do step B1.

  Website opens but shows no data / keeps loading on the logo screen
      -> the API is not running on port 4000. Start it with: npm run dev:api

  "Too many requests"
      -> the request limit was reached. Wait 15 minutes, or restart the
         API (npm run dev:api), or raise RATE_LIMIT_MAX in .env.

  "Too many failed attempts" when signing in
      -> the account is locked for 15 minutes after 5 wrong passwords.

  Port already in use (4000 or 5173)
      -> another copy is still running. Close it, or in PowerShell:
           Get-NetTCPConnection -LocalPort 4000 | Select OwningProcess
           Stop-Process -Id <that number>

  Sample data looks out of date (e.g. no attendance today)
      -> run npm run db:reset (dates are generated for the day it runs).

  Forgot the demo password
      -> it is SEED_DEMO_PASSWORD in .env. If you change it, run
         npm run db:reset again.

  Map is blank
      -> the map tiles come from OpenStreetMap, which needs an internet
         connection.

F. PAPER CORRECTION (AI marking of answer sheets - exam-vision\)
----------------------------------------------------------------------

  Teachers upload handwritten answer sheets (PDF or photos); Claude reads
  them and suggests marks against the teacher's rubric; the teacher checks
  and approves every mark. Approved totals go into an assessment's marks
  register (Assessments), from where they reach Student 360 and report cards.

  Where:     sidebar Academics -> Paper Correction  (/paper-correction)
  Who:       Teacher (exams assigned to them), Principal (creates exams,
             assigns teachers, approves results), Super Admin / School
             Admin (also AI configuration)

  It is a separate Python service in exam-vision\backend. Edunex signs
  users in and forwards their requests, signed with EXAM_VISION_SECRET.
  Students and teachers are copied from Edunex automatically (every
  5 minutes while in use, or "Sync students & staff").

  First time on a PC (Python 3.12+):
     cd exam-vision\backend
     python -m venv .venv
     .venv\Scripts\python.exe -m pip install -r requirements.txt

  .env (already set on this PC):
     EXAM_VISION_URL=http://127.0.0.1:8006
     EXAM_VISION_SECRET=<long random value, 32+ characters>
  Leave EXAM_VISION_URL empty to switch the module off.

  "npm run dev" then starts it with the API and website ([exam] lines).

  Claude key: sign in as Super Admin -> Paper Correction -> AI configuration.
  Enter the key, acknowledge sending pages to Anthropic, Save, then
  "Read a sample page". Without a key, sheets can be uploaded but not read.

  Try it: Principal -> Paper Correction -> New examination (class, section,
  subject) -> Questions & rubrics -> add questions, "Draft with AI" rubrics
  -> Settings tab: assign Ms. Priya Raghavan. Teacher -> upload a sheet ->
  Review -> confirm the student, check each answer, Approve. Principal ->
  Mark as reviewed -> Approve results -> Results & reports -> Send to
  assessment.

  Its data (exams, sheet images, marks, AI settings) is stored in
  exam-vision\backend\data on this PC.

  Tests of the service:  cd exam-vision\backend
                         .venv\Scripts\python.exe -m pytest tests -q

  "Paper Correction is not connected"
      -> the service is not running (look for [exam] lines in npm run dev),
         or EXAM_VISION_URL / EXAM_VISION_SECRET are not set in .env.
  "Paper Correction refused the gateway signature" in the API log
      -> the service was started with a different secret; restart npm run dev.
